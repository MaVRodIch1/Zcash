# ZecMart: минт ZecPuppets с нуля

Пошаговая инструкция: от чистого компьютера до отчёта «какая NFT в каком кошельке».
Предполагается, что ты не видел этот код раньше.

---

## Что вообще происходит

ZecPuppets — коллекция из 555 NFT на лаунчпаде [zecmart.com](https://zecmart.com/launchpad).
Минт **бесплатный**, максимум **2 штуки на кошелёк**, старт в конкретную минуту.

Как устроен минт технически (это важно, чтобы понимать, что делают скрипты):

- Заказ создаётся обычным HTTP-запросом `POST /api/mint/orders`. **Подпись кошельком
  не нужна** — достаточно адреса.
- Коллекция «database-allocated»: NFT выдаёт база сайта, а не блокчейн. Транзакции
  в сети Zcash нет, ZSA-трансфера нет.
- Цена 0 ZEC. **Пополнять кошельки не нужно ничем** — ни ZEC на минт, ни на комиссию.

Отсюда весь смысл инструментов: кошельки нужны только как адреса-идентификаторы,
а сид-фразы — чтобы потом распоряжаться тем, что упало.

### Три скрипта

| Скрипт | Что делает |
|---|---|
| `gen-wallets.mjs` | Создаёт кошельки: сид-фраза + адрес `t1...` на каждый |
| `mint.mjs` | Ждёт старта и рассылает по заказу с каждого кошелька |
| `report.mjs` | После дропа показывает, что в каком кошельке оказалось |

---

## Прежде чем начать: три вещи, о которых лучше знать заранее

**1. Сид-фраза — это и есть кошелёк.** Файл `wallets-secret.json` — единственный ключ
ко всему, что будет заминчено. Потеряешь файл — потеряешь NFT. Покажешь кому-то
12 слов — их заберут. Не вставляй сид-фразы в чаты, скриншоты и заметки. Вообще никуда,
кроме самого кошелька при импорте.

**2. У сайта жёсткий лимит запросов на один IP.** Проверено на практике: восьми
запросов хватило, чтобы получить `HTTP 429` и `Retry-After: 3600` — час бана. Поэтому
скрипт рассылает заказы размеренно, а не пачкой. **Больше кошельков не значит больше
NFT**: при слишком большом списке запуск словит бан на середине, и оставшиеся кошельки
не получат ничего. Разумный диапазон — 10–30 кошельков.

**3. Лимит «2 на кошелёк» поставлен, чтобы дроп разошёлся по людям.** Минт с десятков
своих кошельков — это способ его обойти, и площадки иногда отзывают такие дропы или
банят адреса. Решай сам; просто знай, на что идёшь.

## Шаг 1. Установить Node.js и Git

Нужен **Node.js версии 18 или новее** (лучше LTS) и Git.

- **Windows:** скачай Node.js с [nodejs.org](https://nodejs.org/) (кнопка LTS) и Git
  с [git-scm.com](https://git-scm.com/). Ставь со всеми галками по умолчанию.
- **macOS:** `brew install node git`
- **Linux (Ubuntu/Debian):** `sudo apt update && sudo apt install -y nodejs npm git`

Проверь, что встало (открой PowerShell на Windows или терминал):

```
node --version
```

Должно напечатать `v18.x.x` или выше. Если команда не найдена — перезапусти терминал.

## Шаг 2. Скачать код

```
git clone https://github.com/MaVRodIch1/Zcash.git
cd Zcash
git checkout claude/happy-clarke-xfvyqd
cd zecmart-mint
npm install
```

`npm install` скачает четыре криптобиблиотеки для генерации кошельков и `undici`
для пула соединений. Должно закончиться строчкой вида `added 6 packages`.

## Шаг 3. Решить, где лежат сид-фразы

По умолчанию секретный файл создаётся прямо в папке проекта. Это плохо, если ты
открываешь проект в IDE: PyCharm, например, ведёт Local History и может сохранить
копии. Вынеси файл наружу — один раз задай переменную, и все скрипты будут её видеть.

**Windows (PowerShell):**
```powershell
mkdir "$env:USERPROFILE\Documents\zec" -Force
[Environment]::SetEnvironmentVariable("ZECMART_SECRET", "$env:USERPROFILE\Documents\zec\wallets-secret.json", "User")
$env:ZECMART_SECRET = "$env:USERPROFILE\Documents\zec\wallets-secret.json"
```

**macOS / Linux:**
```bash
mkdir -p ~/zec
echo 'export ZECMART_SECRET=~/zec/wallets-secret.json' >> ~/.bashrc
export ZECMART_SECRET=~/zec/wallets-secret.json
```

Первая длинная строка задаёт переменную навсегда, последняя — на текущий терминал.

## Шаг 4. Проверить, что кошельки создаются правильно

Сначала одноразовый тестовый кошелёк — на него минтить не будем, поэтому его сид
можно спокойно показать на экране.

```
node gen-wallets.mjs --count 1 --secret test-wallet.json --addresses test-wallet.txt
node gen-wallets.mjs --show w001 --secret test-wallet.json
```

Вторая команда напечатает адрес и 12 слов. Теперь:

1. Установи [Noir Wallet](https://chromewebstore.google.com/detail/noir-wallet/mfoghjbpfanobmnoemoepenjjcmfpmdn) в Chrome.
2. Импортируй туда эту сид-фразу как новый кошелёк.
3. Сравни **transparent**-адрес кошелька с тем, что напечатал скрипт.

**Адреса совпали** — значит сид-фразы действительно открывают свои адреса, можно идти
дальше. **Не совпали** — остановись. Минтить на адреса, к которым нет ключей, бессмысленно.

Это единственная настоящая проверка, и пропускать её не стоит: сайт **не проверяет
контрольную сумму адреса** (я скормил ему испорченный — он принял), так что ошибку он
не поймает за тебя.

## Шаг 5. Создать боевые кошельки

```
node gen-wallets.mjs --count 20
node gen-wallets.mjs --verify
```

Создаст 20 кошельков (до 40 NFT) и два файла:

- `wallets.txt` — только адреса. Их читает минтер. Файл безобидный.
- `wallets-secret.json` — сид-фразы. Права 600, в `.gitignore`, наружу не уходит.

`--verify` перевыводит каждый адрес из его сид-фразы заново. Должно сказать
`verify ok: 20 wallets`.

> **Эти сид-фразы на экран не выводи.** Ни `--show`, ни `--print` — до того момента,
> когда после дропа понадобится импортировать конкретный кошелёк.

Нужно больше — `node gen-wallets.mjs --count 10 --append` добавит ещё десять
к существующим. Помни про лимит из предупреждения №2: выше ~30 растёт риск, что
запуск словит бан и остаток кошельков останется ни с чем.

## Шаг 6. Защитить и забэкапить секретный файл

**Windows:**
```powershell
icacls "$env:ZECMART_SECRET" /inheritance:r /grant:r "$($env:USERNAME):(R,W)"
Copy-Item "$env:ZECMART_SECRET" "E:\wallets-secret.json"
```

**macOS / Linux:**
```bash
chmod 600 "$ZECMART_SECRET"
cp "$ZECMART_SECRET" /media/usb/wallets-secret.json
```

Букву диска или путь подставь свои. Бэкап делай **до** минта, а не после.

## Шаг 7. Репетиция

```
node mint.mjs --dry-run --now
```

Проверяет всё, но не отправляет ни одного заказа. В выводе должно быть:

```
wallets loaded: 20
collection: ZecPuppets (zecpuppets) supply=555 available=555
price=0 ZEC  maxPerWallet=2  maxPerOrder=2  quantity=2
preflight ok: 20 wallets usable
=== done: 20/20 wallets got an order ===
```

Если `preflight` ругается на адреса — не запускай боевой минт, разбирайся.

## Шаг 8. Боевой запуск

Минут за 10–15 до старта:

```
node mint.mjs
```

Дальше **окно не трогать**. Скрипт сам:

1. прочитает время старта с сервера и дождётся его (`launch at ... in 3h 37m`),
2. синхронизируется с часами сервера, чтобы не выстрелить раньше или позже,
3. за пару секунд до старта прогреет соединения (экономит ~120 мс на запрос),
4. разошлёт заказы с паузой 300 мс между ними,
5. дождётся финального статуса каждого и запишет `results-<время>.json`.

Узнать точное время старта можно заранее:
```
node -e "fetch('https://zecmart.com/api/mint/launch').then(r=>r.json()).then(console.log)"
```

### Чтобы не проспать дроп

- **Компьютер не должен уснуть.** Windows: `powercfg /change standby-timeout-ac 0`.
  Ноутбук — в розетку, крышку не закрывать.
- **Windows, отдельное окно PowerShell:** отключи QuickEdit (правый клик по заголовку
  окна → Properties → снять галку QuickEdit Mode). Иначе случайный клик мышью внутри
  окна замораживает процесс до нажатия Enter. В терминале PyCharm этой проблемы нет.
- **Если уходишь из дома** — надёжнее запустить на VPS. Туда нужен только `wallets.txt`
  с адресами, секретный файл везти не надо:
  ```bash
  ssh user@сервер
  sudo apt install -y nodejs npm tmux git
  git clone https://github.com/MaVRodIch1/Zcash.git && cd Zcash/zecmart-mint
  git checkout claude/happy-clarke-xfvyqd && npm install
  # скопируй на сервер wallets.txt, затем:
  tmux new -s mint
  node mint.mjs
  # Ctrl+B, потом D — отцепиться, ssh можно закрывать
  # вернуться позже: tmux attach -t mint
  ```

### Если увидишь `!! rate limited ... Retry-After 3600`

Это тот самый бан на час. Запуск остановится сам — так и надо. Повторять бессмысленно:
час ожидания переживёт весь дроп. В следующий раз меньше кошельков и `--gap 500`.

## Шаг 9. Посмотреть, что упало

**Windows:**
```powershell
node report.mjs --orders (Get-ChildItem results-*.json | Sort-Object LastWriteTime | Select-Object -Last 1).Name
```

**macOS / Linux:**
```bash
node report.mjs --orders $(ls -t results-*.json | head -1)
```

Напечатает таблицу «кошелёк → NFT»: лейбл, адрес, номера и картинки предметов,
и итог внизу.

## Шаг 10. Забрать NFT в кошелёк

Для нужного кошелька из отчёта:

```
node gen-wallets.mjs --show w007
```

Полученную сид-фразу вводи **только в само расширение Noir Wallet**, при импорте
нового кошелька. После импорта NFT будут видны на сайте в разделе My Collection
(сайт проверяет и shielded, и transparent адрес подключённого кошелька).

## Шпаргалка по флагам

### `mint.mjs`

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--wallets <файл>` | `wallets.txt` | Список адресов |
| `--quantity <n>` | 2 | Сколько NFT на кошелёк (сервер не даст больше 2) |
| `--concurrency <n>` | 4 | Сколько заказов одновременно |
| `--gap <мс>` | 300 | Пауза между заказами — защита от бана |
| `--lead-ms <мс>` | 250 | На сколько выстрелить раньше старта |
| `--dry-run` | выкл | Проверить всё, ничего не отправляя |
| `--now` | выкл | Не ждать старта |

### `gen-wallets.mjs`

| Флаг | Что делает |
|---|---|
| `--count <n>` | Сколько кошельков создать |
| `--append` | Добавить к существующим, а не заменить |
| `--verify` | Проверить, что каждый адрес выводится из своей сид-фразы |
| `--show <лейбл>` | Показать одну сид-фразу для импорта |
| `--force` | **Перезаписывает файл с сид-фразами. Никогда не используй.** |

## Частые вопросы

**Нужны ли деньги на кошельках?** Нет. Минт бесплатный, транзакций в блокчейне нет,
комиссий нет.

**Я удалил строку из `wallets.txt` — сид-фраза пропала?** Нет. `wallets.txt` — это
просто список адресов для минта. Все сид-фразы лежат в `wallets-secret.json`, и минтер
его даже не открывает. Удалить их может только `--force`.

**Можно ли запустить с одного компьютера несколько раз?** Не стоит: лимит считается
по IP, второй запуск с теми же кошельками словит бан вместо заказов. Повторный запуск
безопасен только если первый не дошёл до отправки — у каждого кошелька свой
idempotency-key, так что дубликат заказа сервер отсечёт.

**Сайт не отвечает / ошибки в `preflight`.** Возможно, поменялось API — оно
недокументированное. Прогони `node mint.mjs --dry-run --now` и смотри на текст ошибки.
